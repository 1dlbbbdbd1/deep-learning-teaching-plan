# PyTorch Debug 工作流

遇到错误时，不先猜答案，先把问题变成可以验证的证据。

## 六步流程

```text
复现问题
→ 缩小输入
→ 提出可验证的假设
→ 增加打印、断点或日志
→ 实施最小修复
→ 添加回归验证
```

## 1. 完整记录现象

- 保存完整报错，不只看最后一行。
- 记录运行命令、Python 版本、设备、输入样本和最近一次改动。
- 区分程序直接报错、结果错误和训练不收敛。
- 分享前删除本机路径、用户名、令牌和其他隐私。

## 2. 缩小问题

- 从完整数据集缩小到一个样本或一个 batch。
- 从完整训练缩小到一次前向传播。
- 从完整模型缩小到出现问题的模块。
- 优先让问题在最短时间内稳定复现。

## 3. 按证据检查

优先检查：

- `shape`：每个模块的输入输出维度。
- `dtype`：图片、标签、权重和 loss 的数据类型。
- `device`：模型和数据是否在同一个设备。
- 数值范围：图片是否归一化，loss 是否为 `nan` 或 `inf`。
- 梯度：是否为 `None`、是否为零、是否爆炸。
- 模式：训练时是否使用 `model.train()`，评估时是否使用 `model.eval()`。
- 预处理：训练和预测是否完全一致。

## 4. 修复后回归

修复不能只看“这次能运行”：

1. 重新运行最小复现。
2. 重新运行单 batch 前向和训练。
3. 重新运行测试集评估。
4. 对关键问题留下自动检查或固定验证步骤。

## 5. 推荐记录方式

复制 [`debug-record-template.md`](debug-record-template.md)，只填写与当前问题有关的证据。
